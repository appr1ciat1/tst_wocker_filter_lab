# 發布數字無法跨下載日重現（2026-07-26）

## 一句話

同一份程式、同一組參數、同一個回測視窗，**只有下載資料的日期差一天**，
v8.5 年化就從 **27.5%** 變成 **18.8%**——差 8.7pp，大於任何一個策略對池的 α。

## 怎麼被發現的

不是刻意去找的。原本在修「對外文案與報表脫節」的問題（SURGE PRO 被標成
「追最高報酬」、崩盤情境被指向最不抗跌的 SURGE），修到一半需要重新產生
paper 頁，重跑後發現 paper 頁的摘要表與四份報表差了 10pp：

| 策略 | paper 重跑（07-24 資料） | 已發布報表（07-16 資料） |
|---|---:|---:|
| v8.5 | 17.0% / −36.7% | 27.5% / −34.7% |
| GUARD | 24.5% / −24.3% | 30.9% / −21.0% |
| SURGE | 33.2% / **−20.4%** | 34.0% / **−29.5%** |
| SURGE PRO | 34.5% / −35.3% | 32.9% / −29.6% |

第一個說不通的地方是 **SURGE 的 MDD 變淺了**（−29.5% → −20.4%）。
最大回撤是路徑上的滾動極值，**多加 8 天資料只可能讓它更深或不變**。
⇒ 兩條路徑跑的不是同一段歷史。

## 排除法

### 不是兩層管線不一致

| 路徑 | 年化 | MDD | Sharpe | 交易 |
|---|---:|---:|---:|---:|
| CLI（`ai_report.py` + workflow 旗標） | 17.17% | −36.7% | 0.784 | 830 |
| 插件（`build_paper_page` → registry） | 17.0% | −36.7% | 0.78 | 830 |

同一天的資料下兩者一致 ⇒ **L3 兩層等價成立**，
`test_param_layer_equivalence.py` 的結論沒有問題。

### 不是股票池縮水

`EXTENDED_TICKERS` 是 115 檔（報表裡的「116」是硬編碼字串），
今天 115 檔全部下載成功（其中 4 檔 `5274/3529/6547/4743` 走 `.TWO` 後援）。

### 不是視窗差異

把 `--end-date` 釘回 `2026-07-16`（與發布報表同視窗）：

| | 年化 | MDD | 交易 |
|---|---:|---:|---:|
| 發布報表（07-25 下載） | 27.5% | −34.7% | 845 |
| 今天重跑（07-26 下載，同視窗） | **18.79%** | −36.7% | 827 |

視窗相同、程式相同、參數相同 ⇒ **只剩資料本身變了**。

## 機制

資料源會**回溯調整歷史價格**。七月是台股除權息旺季，抽樣 40 檔就有 14 檔
在近一個月內除息：

| 代號 | 除息日 | 每股 |
|---|---|---:|
| 2357 華碩 | 2026-07-01 | 42.0 |
| 2454 聯發科 | 2026-07-07 | 24.5 |
| 3034 聯詠 | 2026-07-13 | 23.0 |
| 2382 廣達 | 2026-07-16 | 15.6 |
| 3044 健鼎 | 2026-07-09 | 12.7 |
| 2395 研華 | 2026-07-17 | 11.16 |

（另有 2317 / 3711 / 3037 / 2474 / 2408 / 2303 / 3231 / 2356 共 14 檔）

調整一旦套用，該檔**整段歷史**被重新縮放 → 20 日動量分數改變 →
橫斷面排名改變 → 選到的股票不同 → 整條權益路徑不同。
交易數 845 → 827 正是選股改變的直接證據。

## 影響

1. **既有發布數字事後無法驗證。** `freeze_snapshot` 已實作、`panel_sha256`
   也寫進 metadata，但快照檔被 `.gitignore` 排除（只留 `manifest.json`），
   所以拿不到當初那份面板，無法重現。
2. **不穩定幅度 > 宣稱優勢。** 對池 α 為 +8.2~11.3%（NW t 0.93~1.24，本就不顯著），
   而換一天下載就能讓年化動 8.7pp。
3. **稽核結論方向不受影響。** 「四者 Sharpe 全低於池等權」「2022 全部輸給什麼都不做」
   這類**相對**結論是策略與池在同一份資料上比較，資料一起變、結論方向不變。
   受影響的是**絕對數字**。

## 該做什麼（依優先序）

1. **保留快照**：把 `artifacts/snapshot_*/panel.pkl` 納入版控（或推到 release/LFS），
   讓每次發布可事後重現。現在 `.gitignore` 只留 manifest 等於留了收據沒留貨。
2. **發布時同一份資料跑到底**：報表與 paper 頁必須共用同一次下載
   （目前 CI 是分步各自下載，跨步驟就可能踩到不同的調整狀態）。
3. **量化這個雜訊**：連續 N 天用同視窗重跑，把年化的日間標準差算出來，
   當成所有績效宣稱的誤差棒。沒有誤差棒的單點數字不該再對外呈現。
4. **考慮換未還原資料源 + 自行處理股利**：把「調整」變成自己控制、可版控的一步，
   而不是每天被上游改寫。（注意 FinMind 有零價污染，見既有筆記。）

## 復現方式

```bash
python ai_report.py --no-hybrid-tiered --no-regime-graduated --no-breadth-regime \
  --consec-loss-limit 3 --tp-atr 4.0 --sl-atr 3.0 --hold-days 20 --top-k 7 \
  --gap-filter 1.5 --slippage 0.002 --start-date 2019-01-01 --eval-start 2019-01-01 \
  --end-date 2026-07-16 --artifact-label probe
```

隔幾天再跑一次同一行指令，比對年化。
